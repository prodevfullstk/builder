## 0. Authoritative Mandate & Invariants

> **CRITICAL INVARIANT:**  
> Gate A requires empirical cloud microVM runtime startup and HTTP smoke in an isolated Vercel Sandbox microVM.  
> Untrusted candidate workspaces must execute:  
> `prepare` -> `install` -> `build` -> `start` -> `readiness polling` -> `HTTP smoke request` -> `response validation` -> `terminate process` -> `cleanup sandbox`.  
> No simulation, no synthetic status, no host execution fallback, and no quota reinterpretation.

### 0.1 Inviolable Rules
1. **Zero Evidence Fabrication:**
   - Hardcoded `status: 200`, fabricated URLs, fake readiness timestamps, and static code heuristics masquerading as runtime proof are strictly forbidden.
   - Any evidence object must be dynamically generated by the runner executing in the real isolated microVM.
2. **Isolated MicroVM Execution Exclusively:**
   - Untrusted generated code must NEVER execute on the application server host or developer machine in production mode (`NODE_ENV === "production"`).
   - Execution must use `@vercel/sandbox` remote microVMs with public domain routing and ports exposed.
3. **Fail-Closed Verification & Anti-Forgery:**
   - If sandbox infrastructure or API returns an error or quota exhaustion, emit `RUNTIME_VERIFICATION_UNAVAILABLE` and fail closed.
   - Authoritative CAS commit must strictly reject any candidate without verified real runtime evidence.

## 1. Gate A — Cloud MicroVM Runtime Startup & HTTP Smoke

### 1.1 Requirements Across Frameworks
1. **Next.js (App Router):**
   - Prepare files, run build, start via detached process (`npm run start` or `next start -p <port>`), poll public sandbox domain until ready, execute HTTP GET, validate HTTP 200 and marker content, stop process, and clean up sandbox.
2. **Vite (React):**
   - Prepare files, run build, start preview server (`vite preview --port <port> --host 0.0.0.0`), poll domain, execute HTTP GET, validate HTTP 200 and marker content, stop process, and clean up sandbox.
3. **Astro:**
   - Prepare files, run build, start preview server (`astro preview --port <port> --host 0.0.0.0`), poll domain, execute HTTP GET, validate HTTP 200 and marker content, stop process, and clean up sandbox.

### 1.2 Negative Runtime Test Requirements
- **Build Failure:** Candidate failing build must fail runtime verification, trigger no commit, and preserve previous files and revision.
- **Start Failure:** Server failing to launch must fail verification and prevent commit.
- **Readiness Timeout:** Unresponsive server must timeout, fail verification, and prevent commit.
- **HTTP Failure:** Server returning 4xx/5xx status must fail verification and prevent commit.
- **Sandbox Unavailable:** Infrastructure failure emits `RUNTIME_VERIFICATION_UNAVAILABLE` and prevents commit.
- **Rollback Safety:** Rollback to parent SHA occurs automatically on failed candidate without modifying working tree.

## 2. Resource & Process Safety Policy
- Detached processes in sandbox must be stopped and killed (`pkill -f node`).
- Temporary sandbox resources must be deleted with `deleteOrphanSnapshots: true`.
- No orphaned sandbox sessions or memory leaks permitted.
